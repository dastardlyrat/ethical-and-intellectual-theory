## Scope and contribution roles

This is the expressly approved public projection of a bounded programming doctrine. It preserves human-authored theory and human-composed decomposition, while identifying AI-assisted formulation, mappings, automation, examples, and finite checks. It makes no claim about personal identity, individual uniqueness, psychology, or a complete greater ethical theory.

Publication preserves the distinction between confirmed commitments, recovered requirements, proposed operational formulations, conditional arguments, illustrative cases, and historical observations. Neither publication nor structural validity turns every retained formulation into universally adopted policy.

## Privacy projection

The public edition removes direct identifiers, workstation and internal workspace paths, original chat identifiers and turn positions, source inventory fingerprints, recovery references, source-origin metadata, and embedded historical source dumps. The original local extraction is preserved unchanged. The exact alias and transformation map remains private and is not part of either public repository.

There are 283 neutral source aliases. They preserve source-role distinctions and internal correspondence without exposing original locations. Original method-item text and private item positions remain in the private reconciliation; public dispositions retain the current target and the reason for any qualification.

Source availability is stated honestly: the underlying private basis is retained but not published here. A neutral alias does not make that basis independently inspectable. Qualifications that previously pointed into removed payloads now describe the private retention accurately. These provenance edits do not alter the operative statements, method steps, conditions, or adoption status.

The content is de-identified. Distinctive ideas and the hosting accounts may still create associations; no guarantee of unrecognizability or anonymity against every correlation is made. Publication of this supplied doctrine does not supply general consent for unrelated personal profiling, identity authentication, or imitation.

## Presentation, integrity, and evidence limits

All six public files are screened as complete bytes. The screen covers known names/accounts, private path forms, contacts, chat identifiers, original source namespaces, original UUID forms, private source fingerprints, credential patterns, and replacement characters. The manifest necessarily contains the public payload digests; it contains no private input fingerprints. These finite checks do not prove that every conceivable identifying correlation has been removed.

The human documents use core Markdown headings, paragraphs, lists, code spans, and the retained fenced Python reference. Current record projections, links, heading fragments, literal sentinel markers, UTF-8/LF text, and paired code fences are checked. No screen capture, screen sharing, UI automation, or native rendered-preview verification is performed.

The manifest covers the five component payloads and excludes itself. It identifies observed public bytes; it does not establish source authenticity, trusted chronology, authorship, authorization, or semantic truth. Repository-root navigation is outside the component manifest and is verified separately with the committed repository tree.

Earlier runtime results remain historical claims within the declared example profile. Publication does not rerun those tests or establish general code synthesis, arbitrary-input hardening, cross-version behavior, crash recovery, external-effect preservation, formal proof, runtime enforcement, or production acceptance.

The publication adds this component and reading links while preserving existing repository content and history. It introduces no new license, changes no repository visibility, installs no global instructions, and activates no executable system.
